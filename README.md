# RANKUP — 두뇌 랭크전

**▶ https://17vs01.github.io/rankup/**

심심할 때 쇼츠 대신 여는 앱. 열면 바로 할 게 있고, **한 판 60초**, 끄고 나면 실력이 숫자로 남는다.

폰 브라우저로 위 주소를 열고 **홈 화면에 추가**하면 앱처럼 쓸 수 있다. 오프라인에서도 돌아간다.

## 왜 이렇게 만들었나

쇼츠/틱톡이 이기는 이유는 재미가 아니라 **마찰이 0**이기 때문이다. 그래서 같은 조건을 맞췄다.

| 조건 | 쇼츠 | RANKUP |
|---|---|---|
| 열자마자 할 게 있나 | O | O (선택 화면 없음, 빠른 시작 1탭) |
| 30초 세션 성립 | O | O (60초 한 판) |
| 콘텐츠 고갈 | 없음 | 없음 (문제 절차 생성) |
| 끄고 나서 남는 것 | **없음** | **랭크 + 실제 실력** |

의지력으로 쇼츠를 참는 게 아니라, 같은 습관 자리를 뺏는 쪽으로 설계했다.

### 🎭 예측 불가 — 이 앱의 핵심

1953년 벨연구소에서 클로드 섀넌이 만든 "마인드 리딩 머신"을 폰으로 옮긴 것. 사람은 무작위를 못 만든다 — "아무렇게나" 누른다고 믿어도 반드시 버릇이 남는다.

좌/우 버튼 두 개로 60번. 매번 AI가 **먼저** 예측하고, 누른 뒤에 맞았는지 공개된다.

- AI는 다중 차수 마르코프 예측기다. 랭크가 오르면 기억하는 문맥이 2수 → 8수로 늘고, 1400 LP부터는 **누르는 속도(리듬)**까지 문맥에 넣는다.
- 적중률 44%까지 떨어뜨리면 본전, 50%(완전 무작위)면 상승.

봇으로 검증한 결과:

| 플레이 방식 | AI 적중률 | LP |
|---|---|---|
| 인간형(70% 교대 편향) | 58% | −1 |
| 진짜 무작위 | 47% | **+7** |

사람이 "무작위"라고 착각하는 패턴은 실제로 읽힌다.

### 💥 연쇄 스도쿠 — 설계를 한 번 뒤집었다

원래는 "최소 입력으로 판을 완성하기"였다. 그런데 측정해보니 **단서 22~26개 어디서든 최적해가 항상 1수**였다. 스도쿠는 병목 한 칸만 뚫으면 나머지가 전부 싱글로 무너지기 때문이다. 최적이 1이면 실력 차가 드러날 자리가 없다.

| 단서 | 시작 빈칸 | 무작위 입력 | 최적 입력 |
|---|---|---|---|
| 26 | 42.3 | 1.8 | **1.0** |
| 24 | 40.8 | 2.0 | **1.0** |
| 22 | 45.8 | 2.2 | **1.0** |

그래서 판 하나를 오래 붙드는 대신 **막힌 판을 4개 내고 매번 그 한 칸을 찾게** 바꿨다. 뚫으면 도미노가 터지고 다음 판으로 넘어간다.

난이도는 3단계로 갈린다. 막힌 판은 단독후보·숨은단독이 이미 소진돼 있어 포인팅 페어 같은 고급 기법이 필요한데, 브론즈에게 그걸 요구하면 한 칸도 못 뚫는다.

- **~1200 LP**: 싱글이 살아 있는 판 + 후보 자동 표시 → 찾기 쉽고 연쇄는 그대로 크다 (한 수에 ~46칸)
- **1200~1600**: 완전히 막힌 판 + 후보 표시
- **1600+**: 완전히 막힌 판, 후보 없음 (직접 세야 함)

### 🎯 확신도 — 정답률이 아니라 자기평가를 채점한다

답을 고른 뒤 확신도(50~100%)를 함께 찍는다. 채점은 브라이어 점수 `(확신도 − 실제결과)²`. 90% 확신하고 틀리면 크게 깎이고, 60% 확신하고 틀리면 거의 안 깎인다.

봇 검증:

| 플레이 방식 | 판정 | LP |
|---|---|---|
| 전부 100% 확신 | 정답 5/10, **과신 +50%p** | −24 |
| 아는 건 100%, 모르는 건 50% | 정답 8/10, **균형** | **+9** |

정답을 더 맞힌 쪽이 아니라, 자기 실력을 정확히 안 쪽이 이긴다.

## 랭크 시스템

**브론즈 → 실버 → 골드 → 플래티넘 → 다이아 → 마스터 → 그랜드마스터** (1000 LP 시작)

- **ELO 방식**: 절대 점수가 아니라 *현재 레이팅의 기대치 대비* 성과로 LP가 오르내린다. 한 판 최대 **+40 / -24**.
- **난이도 자동 추적**: 레이팅이 오르면 문제도 어려워진다. 암산은 `3+5`에서 시작해 `47×63`, `38²`까지 간다. 그래서 정답 개수는 실력이 늘어도 비슷하게 유지되고, **오르는 건 랭크뿐**이다.
- **어휘 난이도**: 레이팅 400마다 단어 티어가 오른다 (기초 → 수능 → 토익 고득점 → GRE급).
- **기억력 적응형**: 성공하면 +1칸, 실패하면 -1칸. 매 판 자기 한계선에서 논다.
- **눈대중·체내 시계**: 레벨이 오르면 허용 오차가 조여든다 (±14% → ±2.5%). 체내 시계는 2단계부터 **엉뚱한 속도로 차오르는 가짜 진행바**가 붙어 체감을 흔든다.
- **나침반**: 지시가 3단계에서 12단계로 늘고 표시 속도가 빨라진다. 정답 8방위가 균등하게 나오도록 경로를 역으로 뽑기 때문에 "그냥 뒤 찍기"가 통하지 않는다.

### 패널티 — 방치 부식

**48시간** 안 하면 하루 **-8 LP**씩 깎인다. 단, **최고점 -250**에서 멈춘다 (며칠 쉬었다고 바닥까지 떨어지진 않음).

홈 화면에 부식까지 남은 시간이 표시되고, 깎였으면 경고 배너가 뜬다. 이게 "오늘 한 판" 하게 만드는 장치다.

### 라이트너 복습 (어휘)

틀린 단어는 다음 판에 바로 다시 나온다. 맞히면 1일 → 2일 → 3일... 간격으로 밀린다. 반복만 해도 어휘가 실제로 쌓인다.

## 폰에서 쓰기

### 방법 A — 맛보기 (같은 와이파이, 5초)

PC에서 서버를 켜고 폰으로 접속한다.

```bash
npx -y http-server C:\projects2\enjoy -p 8734 -c-1
```

`ipconfig`로 `IPv4 주소`를 확인해서 폰 브라우저에 `http://<그 IP>:8734` 입력.

> ⚠️ **이 방식은 오프라인이 안 된다.** 서비스워커는 HTTPS 또는 localhost에서만 등록되는데
> `http://192.168.x.x`는 둘 다 아니다. 그래서 PC 서버가 꺼지면 앱도 안 열리고,
> Android Chrome의 "앱 설치"도 안 뜬다. 게임과 랭크 기록 자체는 정상 동작한다.
> 포트가 이미 쓰이는 중이면 `EADDRINUSE` 에러가 난다 — 서버가 이미 떠 있다는 뜻이니 그냥 접속하면 된다.

### 방법 B — 배포본 쓰기 (권장)

이미 GitHub Pages에 올라가 있다. 폰에서 그냥 열면 된다.

**https://17vs01.github.io/rankup/**

고친 뒤 다시 올리려면 푸시만 하면 된다 (빌드 과정 없음):

```bash
git push
```

> 배포 후 캐시된 옛 버전이 보이면 `sw.js`의 `CACHE` 값을 올려서 푸시한다.
> 서비스워커는 네트워크 우선이라 보통은 그냥 갱신된다.

폰에서 열고 **홈 화면에 추가**:
- iPhone(Safari): 공유 버튼 → `홈 화면에 추가`
- Android(Chrome): ⋮ → `앱 설치`

이제 서비스워커가 전부 캐싱해서 **비행기 모드에서도** 돌아간다. 기록은 폰 localStorage에 남는다.

> 기록이 브라우저 저장소에만 있어서, 브라우저 데이터를 지우면 랭크가 날아간다.
> 몇 달 쌓을 거라면 JSON 내보내기/가져오기를 붙이는 걸 권한다.

### 게임 추가하는 법

`js/games/`에 아래 형태로 만들고 `main.js`의 `GAMES` 배열에 넣으면 끝. 랭크·부식·기록은 자동으로 붙는다.

```js
export const myGame = {
  id: 'mygame', name: '이름', icon: '🎯', desc: '한 줄 설명',
  run(ctx) {
    // ctx.rating    현재 레이팅 → 난이도 조절에 사용
    // ctx.body      게임 DOM 컨테이너
    // ctx.delay()   세션 종료 시 자동 정리되는 setTimeout
    // ctx.timer(초, 콜백)   상단 카운트다운
    // ctx.stopwatch()       흐르는 시간 (제한 없는 종목용). 경과초를 읽는 함수를 반환
    // ctx.persist()         state 저장 (스도쿠 이어하기 등)
    // ctx.onAbort = fn      ✕ 누르기 직전 호출 — 진행 상황 저장에 쓴다
    // ctx.setTitle(문자열)
    // ctx.finish({ score, perf, detail })
    //   perf = 실제성과 / 기대성과. 1.0이면 LP 변동 0.
  },
};
```

`perf`만 제대로 잡으면 랭크가 자기평형을 이룬다. 기대치를 현재 레이팅에 비례하게 두는 것이 핵심.
